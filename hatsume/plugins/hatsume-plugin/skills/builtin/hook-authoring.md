# Hook Authoring

当用户希望机器人持续监听收件箱、外部 API、文件或其他可轮询来源的变化时，使用本 Skill。

## 先判断是否适合 Hook

- Hook 只适合“状态发生变化时通知或处理”的增量检查。
- 固定时间提醒应使用 Timer；一次性任务直接执行。
- 拒绝没有实际监听价值、会制造无用调用、或一次检查天然需要数分钟的请求。
- 只有当前请求者是管理员且明确坚持时，才能接受上述语义上不推荐的需求；程序限制仍不能绕过。
- 每群最多启用 5 个 Hook；全部 Hook 的间隔至少 300 秒，单次超时最多 60 秒。

## 编写位置与结构

1. 使用 coding_agent 在 `data/hatsume-plugin/hooks/<当前群号>/` 下写脚本和状态。
2. 脚本必须是带 shebang 的可执行普通文件，不得使用交互输入、daemon、自行常驻或遗留后台子进程。
3. 从环境变量或权限受限的配置读取凭证；禁止把 token、密码或密钥写进脚本、stdout 或错误信息。
4. 使用邮件 UID、API 游标、时间戳或内容 ID 做增量检查，以原子替换方式写入持久游标，保证同一事件不会反复报告。
5. 根据来源成本和新鲜度选择保守间隔。除非确有需要，不要默认使用最短 300 秒。

## 严格退出协议

- 没有新事件：stdout 保持为空，退出码为 `0`。
- 有新事件：stdout 只输出给 chat_agent 所需的简洁、无秘密事件上下文，退出码为 `10`。
- 检查失败：诊断写入 stderr，使用 `0` 和 `10` 以外的退出码。
- 不要用日志污染 stdout。一次运行最多输出 8 KiB stdout。

## 无副作用验证模式

工具在创建或替换脚本前会设置 `HATSUME_HOOK_VALIDATION=1` 运行脚本。此模式可以读取并检查外部来源，但不得创建、推进或替换持久游标，也不得产生其他外部副作用。验证时即使退出 `10` 也不会触发 chat_agent。

在注册前至少以验证模式手动运行两次，并确认无变化的一次 stdout 为空且 exit `0`。脚本必须能在所选 `timeout_seconds` 内稳定结束。

## 注册

确认脚本满足协议后调用 `create_hook`，传入：

- 清晰且在当前群唯一的名称；
- 当前群 Hook 目录内的绝对脚本路径；
- 触发后 chat_agent 应如何处理事件的 prompt；
- 你根据来源选择的 `interval_seconds`（至少 300）；
- `timeout_seconds`（1 至 60，默认 15）。

创建后向用户说明实际间隔、超时和 Hook 名称。使用 `list_hooks` 检查调度状态；修改用 `update_hook`，删除用 `delete_hook`。删除 Hook 不会删除脚本和游标文件。
