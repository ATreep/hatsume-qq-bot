# Feature Specification: 自动回复上下文窗口优化

**Feature Branch**: `006-auto-reply-context-window`

**Created**: 2026-06-04

**Status**: Draft

**Input**: User description: "机器人的自动回复应该只针对最近10条消息进行回复（但前面的20条回复仍需要输入给AI，帮助机器人了解背景信息），你应该在向机器人输入自动回复的聊天历史记录时，将最新的10条记录与历史20条记录作区分。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自动回复聚焦最近聊天话题 (Priority: P1)

群聊成员在低活跃度群中聊天时，机器人触发自动回复后，回复内容应围绕最近的聊天话题展开，而不是几小时前的旧话题。

**Why this priority**: 这是本功能的核心价值——解决机器人回复过时聊天内容的根本问题，直接影响用户体验。

**Independent Test**: 在测试群中发送超过30条消息（模拟低活跃场景，让消息跨越数小时），验证机器人自动回复时是否只针对最近10条消息的话题进行回应。

**Acceptance Scenarios**:

1. **Given** 群聊中已累积30条消息（最新10条讨论"天气"，前20条讨论"游戏"），**When** 机器人触发自动回复，**Then** 机器人应围绕"天气"话题回复，而不是"游戏"
2. **Given** 群聊中已累积30条消息（最新10条为闲聊），**When** 机器人触发自动回复，**Then** 机器人应针对最近的闲聊内容回复

---

### User Story 2 - AI获得完整背景信息用于理解上下文 (Priority: P1)

当机器人触发自动回复时，AI模型应能同时看到最近10条"当前消息"和前20条"历史消息"，以便理解对话的来龙去脉，做出连贯的回复。

**Why this priority**: 仅提供最近10条消息可能导致AI缺乏足够上下文做出合理回复，历史20条消息作为背景信息是生成高质量回复的必要条件。

**Independent Test**: 检查自动回复时提供给AI的消息上下文，验证是否包含明确区分的"当前聊天记录"（10条）和"历史聊天记录"（20条）两部分。

**Acceptance Scenarios**:

1. **Given** 群聊中已累积30条消息，**When** 机器人触发自动回复并将上下文传递给AI，**Then** AI收到的消息中明确区分"当前聊天记录"（最新10条）和"历史聊天记录"（前20条）
2. **Given** AI收到区分后的消息上下文，**When** AI生成回复，**Then** 回复内容应体现出对最近话题的侧重和对历史背景的理解

---

### User Story 3 - 低活跃群聊不触发对过时内容的回复 (Priority: P2)

在低活跃度的群聊中（如数小时才有几条消息），机器人的自动回复机制应避免将跨越数小时的旧消息作为当前话题来回应。

**Why this priority**: 这是问题最明显的场景——在低活跃群中旧消息被当作当前话题回复最为尴尬，但不影响核心的消息分层机制。

**Independent Test**: 在低活跃群中模拟数小时的消息间隔，验证机器人的回复是否围绕最新消息。可以通过检查触发自动回复时传递给AI的"当前聊天记录"是否只包含最新10条来验证。

**Acceptance Scenarios**:

1. **Given** 群聊中消息跨越5小时才累积满30条，**When** 机器人触发自动回复，**Then** 机器人的回复话题应聚焦于最近到达的消息内容
2. **Given** 群聊消息时间跨度大但最新消息无实质内容，**When** 机器人触发自动回复，**Then** 机器人不应强行回复，可以选择不回复（取决于现有的自然结束检测逻辑）

---

### Edge Cases

- 当累积消息总数不足30条时触发主动回复的边界情况（例如：20条消息时通过其他方式触发回复），应按可用消息数量合理分配"当前"和"历史"消息
- 当消息总数少于10条时，全部作为"当前聊天记录"，不显示"历史聊天记录"部分
- 消息中包含图片、合并转发等非文本内容时，应保持这些内容的完整性，并在计数时视为一条消息
- 配置值（最近10条 / 历史20条）应可调整，以适应不同场景需求

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统在构建自动回复的消息上下文时，必须将消息分为"当前聊天记录"和"历史聊天记录"两部分
- **FR-002**: "当前聊天记录"默认包含自动回复触发批次中的最新 N 条消息（N 默认为 10）
- **FR-003**: "历史聊天记录"默认包含"当前聊天记录"之前的最多 M 条消息（M 默认为 20）
- **FR-004**: 在传递给 AI 模型的消息中，必须使用明确的标记（如"## 当前聊天记录："和"## 历史聊天记录："）区分两部分消息
- **FR-005**: 历史聊天记录与当前聊天记录不应有重叠（同一条消息不能同时出现在两部分中）
- **FR-006**: 系统必须支持通过配置修改 N（当前消息数）和 M（历史消息数）的值
- **FR-007**: 当总消息数不足 N+M 时，系统应优先满足"当前聊天记录"的数量要求，然后以剩余消息填充"历史聊天记录"

### Key Entities *(include if feature involves data)*

- **当前聊天记录（Current Context）**: 触发自动回复时批次中最新的一组消息，代表机器人需要直接回应的近期话题。包含消息内容、发送者、消息类型等属性。
- **历史聊天记录（Historical Context）**: 当前聊天记录之前的一组消息，为 AI 提供对话背景但不作为直接回复目标。包含与当前聊天记录相同的消息属性。
- **上下文配置（Context Config）**: 控制当前/历史消息数量的可调参数，包括当前消息数（N）和历史消息数（M）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 机器人自动回复的话题相关性提升——在低活跃群聊中，回复内容与最近消息的话题一致率显著高于当前基线（当前基线：机器人经常回复几小时前的旧话题）
- **SC-002**: 群成员感知到的"机器人回复过时内容"投诉或反馈减少
- **SC-003**: AI 模型在获得区分后的上下文后，生成的回复质量不下降（即添加"历史聊天记录"背景信息不会导致回复质量恶化）
- **SC-004**: 自动回复仍能在 30 条消息累积后及时触发，不会因上下文分层引入额外延迟

## Assumptions

- 当前自动回复触发机制（30条消息累积 + has_respond_recently 交替跳过）保持不变，本功能仅修改消息如何传递给 AI 模型
- 现有的 `human_node` 中已有的 "## 历史聊天记录：" / "## 当前聊天记录：" 标记模式可以复用和扩展
- 消息的"新旧"按照在 idle_queue 中的顺序判断：索引越大的消息越新
- N=10 和 M=20 作为默认值是合理的起点，可以根据实际效果调优
