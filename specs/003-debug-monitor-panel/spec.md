# Feature Specification: 实时调试监控面板

**Feature Branch**: `003-debug-monitor-panel`

**Created**: 2026-06-01

**Status**: Draft

**Input**: User description: "为机器人创建一个前端的实时监控调试面板，支持可视化实时查看机器人各个实时状态的变量值，方便进行调试。风格极简，多半透明毛玻璃样式，多圆角，尽可能不使用带阴影的设计。在启动 NoneBot 时自动启动前端。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连接监控面板并查看实时状态 (Priority: P1)

作为机器人开发者，我希望在浏览器中打开一个调试页面，实时看到机器人所有模块的运行时状态变量，以便快速了解当前运行状况。

**Why this priority**: 这是面板的核心功能——没有实时状态可视化，调试面板就失去了存在意义。

**Independent Test**: 启动机器人后，在浏览器访问调试面板 URL，观察面板是否正确显示各模块的变量名和当前值，值是否随机器人状态变化而自动更新。

**Acceptance Scenarios**:

1. **Given** 机器人已启动运行, **When** 开发者在浏览器中打开监控面板 URL, **Then** 面板显示所有已注册模块的状态变量及其当前值，连接状态指示为"已连接"
2. **Given** 监控面板已连接并显示状态, **When** 机器人内部某个状态变量发生变化（如开始对话、队列长度增减）, **Then** 面板中对应该变量的显示值在 500ms 内自动更新
3. **Given** 监控面板已连接, **When** WebSocket 连接意外断开, **Then** 面板显示"断开连接"状态指示，并在连接恢复后自动重新加载数据

---

### User Story 2 - 按模块浏览变量 (Priority: P2)

作为开发者，我希望调试面板将状态变量按所属模块分组展示，以便快速定位到需要关注的特定模块。

**Why this priority**: 随着监控变量增多（约 25 个分布在 6 个模块中），未分组的平铺列表会难以快速定位。模块分组是可用性的必要提升。

**Independent Test**: 打开面板后，左侧显示模块列表，点击某个模块后右侧区域仅显示该模块的变量。

**Acceptance Scenarios**:

1. **Given** 面板已连接, **When** 开发者查看左侧模块列表, **Then** 所有已注册模块按名称排列，每个模块旁显示其包含的变量计数
2. **Given** 左侧模块列表可见, **When** 开发者点击某个模块名, **Then** 右侧区域更新为仅显示该模块的变量及其当前值
3. **Given** 面板刚打开, **When** 未选择任何模块, **Then** 默认显示第一个模块的变量

---

### User Story 3 - 变量值变化高亮 (Priority: P3)

作为开发者，我希望在某个变量值发生变化时能看到视觉提示，以便快速注意到状态变动。

**Why this priority**: 当面板上有大量变量时，人工比对数个变量来发现变化是低效的。变化高亮让开发者无需持续注视即可注意到变动。

**Independent Test**: 触发某个变量值变化，观察面板上该变量的显示区域是否短暂闪烁。

**Acceptance Scenarios**:

1. **Given** 面板正在显示某个模块的变量, **When** 其中某个变量的值发生变化, **Then** 该变量的卡片在 300ms 内显示短暂的背景色闪烁动画
2. **Given** 多个变量同时发生变化, **When** 下一轮数据推送到达, **Then** 所有变化变量的卡片同时闪烁

---

### Edge Cases

- 监控面板首次打开时，WebSocket 尚未建立连接：面板显示"连接中…"加载状态，连接成功后自动拉取数据
- 浏览器 Tab 长时间处于后台后切回：WS 可能断开，自动重连后恢复显示
- 机器人尚未完全初始化（变量为 None/null）：面板正常显示 `null` 或 `—`
- 极少数情况下某一轮采集失败（抛出异常）：跳过本轮，前端保留上一次有效数据，不崩溃
- 嵌套数据结构（dict）的显示：自动展开为子项列表，每个 key 作为子卡片显示
- 列表类型变量的显示：显示列表长度计数，点击可展开查看内容摘要

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在 NoneBot 启动时自动注册调试面板的 HTTP 路由和 WebSocket 端点，无需开发者手动触发
- **FR-002**: 系统 MUST 提供 HTTP 端点返回包含完整监控 UI 的单文件 HTML 页面（内联 CSS 和 JS，无外部依赖）
- **FR-003**: 系统 MUST 提供 WebSocket 端点，首次连接时推送所有模块状态变量的全量快照，之后每轮以最小 diff 形式推送变更值
- **FR-004**: 系统 MUST 支持按模块注册状态采集器，每个采集器包含模块名称和一个返回键值对的采集函数
- **FR-005**: 前端 MUST 以左侧模块导航 + 右侧变量详情的布局展示监控数据
- **FR-006**: 前端 MUST 在变量值变动时（与上一轮数据对比不同）对该变量卡片触发 300ms 的背景色闪烁动画
- **FR-007**: 前端 MUST 在 WebSocket 连接断开时显示断开状态指示，并在恢复后自动重连
- **FR-008**: 前端视觉风格 MUST 遵循：半透明毛玻璃面板、深色底色、大量圆角、1px 半透明边框分隔、不使用投影阴影
- **FR-009**: 监控面板页面整体大小 MUST 不超过 15KB（压缩前），不含任何外部 CSS/JS/font 引用
- **FR-010**: 布尔类型变量 MUST 以彩色圆点（绿色=true/灰色=false）直观显示
- **FR-011**: int/float 类型变量 MUST 以右对齐等宽字体数字显示
- **FR-012**: 列表类型变量 MUST 显示元素计数，单击可展开查看前 N 项摘要
- **FR-013**: dict 类型变量 MUST 递归展开为嵌套变量卡片组
- **FR-014**: 系统 MUST 监控以下模块的运行时状态：会话状态、AI 节点、工具调用、记忆系统、基础设施、夜间漫画

### Key Entities

- **StateCollector（状态采集器）**: 代表一组相关状态变量的集合。包含模块名称（如 "conv_state"）和一个采集函数，调用后返回键值对字典。每个键为变量名，值为当前快照。
- **StateSnapshot（状态快照）**: 某一时刻所有已注册采集器的状态全集。由所有 StateCollector 的采集结果合并而成，按模块组织。
- **StateDiff（状态变更）**: 相邻两轮快照的差异。仅包含值发生变化的键，以及新增/删除的键。最小化 WebSocket 推送数据量。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 开发者从机器人启动到能在浏览器中打开调试面板的时间不超过 3 秒（启动即就绪）
- **SC-002**: 变量值变化后，前端在 500ms 内反映最新值
- **SC-003**: 状态采集器单轮采集（10 个采集器）的时间开销不超过 10ms，不阻塞主事件循环
- **SC-004**: 监控面板在浏览器中的内存占用量不超过 30MB（包含 WebSocket 连接），不随运行时长持续增长
- **SC-005**: 面板页面在 3G 网络下初次加载时间不超过 2 秒
- **SC-006**: 开发者能一眼辨识变量是否变化（闪烁动画 + 颜色区分），无需对比前后数值
- **SC-007**: 开发者无需查阅文档即可理解每个变量的含义（模块分组 + 变量名清晰命名）

## Assumptions

- 机器人运行环境已具备 FastAPI 和 WebSocket 支持（NoneBot2 的 fastapi 驱动已配置）
- 调试面板仅面向开发者使用，不考虑多用户并发访问或权限控制
- 目标浏览器支持现代 Web 标准（ES2020+、CSS backdrop-filter、WebSocket API）
- 调试面板不需要持久化任何数据，纯内存运行
- 默认轮询间隔 500ms，开发者可通过 URL 参数调整
- 面板仅监听 localhost 或内网，不做外网暴露
